## 0. 方向（一句话）

> **边缘端故意“宁可多报”保召回，云端把边缘报出的每个框裁下来做“缺陷 / 背景”分类，把虚警筛掉；中间用学习型路由决定“哪些框值得花云端算力”。**

和旧方案最大的区别：**云端的任务从“再检测一遍”变成“判这个框是真是假”。**

## 1. 已经完成的部分（三条支柱 + 三张底牌）

### 三条支柱

| 产出 | 文件 | 说明 |
|---|---|---|
| 八个模型横评 | `compare_summary.csv`、`fig_model_compare.png` | v8n/s/m、v9t、v10n、v11n、v12n、v26n，**已封盘** |
| 静态阈值扫参 | `tau_summary.csv`、`fig_tau_curve.png` | 证明 p95 是上云比例的阶梯函数 |
| 逐框评估 | `tools/eval_metrics.py`、`froc.csv`、`metrics_by_class.csv`、`fig_froc.png` | 接了 GT，算出真 Recall / FPPI |

### 三张底牌（汇报时张口就来）

| 结论 | 数据 |
|---|---|
| **边缘单跑不够** | conf=0.5 时 Recall **0.603**，漏掉 40% |
| **短板只有一类** | crazing：140 个真缺陷只抓到 46 个，**漏 67%**；其余五类均 ≥0.73 |
| **降阈值能换召回** | conf 0.5→0.15，Recall **0.603→0.794**，代价每图多 1.2 个虚警 |

### 已定的结论（不再讨论）

1. 边缘模型定 **v9t**（mAP50 0.7607，8.3MB，CPU 39ms）——v8m 又大又慢效果更差
2. **P2 小目标头不做**：crazing 框占图 21%，最小类中位也 40×40，数据集里没有小目标
3. **云端不用大模型整图重检**：原图仅 200×200，放大到 960 是插值，且 v8m 在 crazing 上比 v9t 还差
4. **mAP 降为参考指标**，主指标是 Recall + FPPI

### 两个人的硬要求

**给绝：**
1. 训练用 **GT 框**裁块，推理才用检测框裁（避免误差级联）
2. **必须有背景负样本**（从 GT 框以外裁），这是云端能不能驳回误报的前提
3. **不许报总准确率**，只认 crazing 行和 background 行

**给大二A：**
1. 不做前后端分离、数据库、Docker、鉴权——就两个 `.py`
2. **RTT 必须可配且单独计段**，混进云端耗时里就证明不了“网络是瓶颈”
3. 四段延迟：`edge_ms` / `route_ms` / `rtt_ms` / `cloud_ms`

## 7. 协作机制

1. **周会**：每周一 20:00，30 分钟。每人 3 分钟：上周交了什么（**报文件名**）、本周交什么、卡在哪。
2. **产出目录**：`runs/YYYYMMDD_<内容>/`，内含 `README.md` 写清怎么跑、产出是什么、谁做的。
3. **不许覆盖别人的文件**：要改先复制，加自己名字后缀。
4. **数据文件必须自描述**：所有 csv 的第一列或表头必须写明工作点/参数，不许只靠“我还记得”。
5. **权重不进 git，走网盘**；代码和文档进 git。
